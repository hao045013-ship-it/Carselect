## 三、核心架构约束

```
1. 所有知识源只受 Controller 调度
2. 知识源之间禁止直接通信（通过黑板间接共享数据）
3. 知识源与控制器之间仅通过 MQ 通信
4. 知识源通过读写 Redis 黑板共享数据
5. 知识源不知道彼此的存在
6. TP/Navigator 不写 CarID:Status（由Controller控制状态变迁）
7. Controller 是唯一调度者，按节拍（tick）驱动
```

## 四、时序协作

### 启动流程

```
TaskConfigurator
  初始化地图（mapBlock随机障碍）
  初始化小车（5辆，位置/状态/视野）
  声明所有MQ队列
  → 发 TASK_READY 到 ControllerCmd

Controller 收到 TASK_READY
  → 开始节拍循环

Registry
  → 各知识源启动时注册
  → 黑板记录在线列表
```

### 主节拍流程

```
每 tick:
  1. Controller 读所有 Car:Status
  2. Status=IDLE  → 发 ASSIGN_TARGET 给 TargetPlanner
  3. TargetPlanner 写 Target → 回复 TARGET_ASSIGNED
  4. Controller 写 Status=WAITING_ROUTE
  5. Status=WAITING_ROUTE → 发 PLAN_ROUTE 给 Navigator
  6. Navigator 读 Target+Position → BFS → 写 RouteList → 回复 ROUTE_PLANNED
  7. Controller 写 Status=READY
  8. 所有 READY 的车 → 发 TICK_MOVE
  9. Car 移动一步 → 回复 MOVED/BLOCKED/ROUTE_DONE
  10. 广播 UpdateView（通知所有订阅者刷新）
```

### 障碍物设置流程

```
Web 前端用户点击"随机生成"或手动点击格子
  → WebSocket 发到 CommandReceiver
  → CommandReceiver 转发到 OblastacleManager 队列（或直接处理）
  → ObstacleManager 写 mapBlock
  → 通知 Controller 刷新
```

### 回放流程

```
每节拍 ReplayLogger 收 UpdateView
  → 读全量黑板状态
  → 存入 replay:snapshots (List)
  
回放时前端请求 → WebSocketBridge 读取快照 → 推送给浏览器逐帧播放
```

## 七、消息类型汇总

| 消息类型 | cmd | 方向 | data字段 |
|---------|-----|------|---------|
| 配置 | `FORWARD_CONFIG` | Controller→TaskConfig | {mapWidth,mapHeight,carCount,obstacleDensity,algorithm} |
| 重置 | `FORWARD_RESET` | Controller→TaskConfig | {} |
| 目标分配 | `ASSIGN_TARGET` | Controller→TargetPlanner | {carId} |
| 路径规划 | `PLAN_ROUTE` | Controller→Navigator | {carId, algorithm} |
| 节拍移动 | `TICK_MOVE` | Controller→Car | {} |
| 任务就绪 | `TASK_READY` | TaskConfig→Controller | {carCount,mapWidth,mapHeight} |
| 目标已分配 | `TARGET_ASSIGNED` | TargetPlanner→Controller | {assignedCars:[{carId,targetX,targetY}]} |
| 路径已规划 | `ROUTE_PLANNED` | Navigator→Controller | {carId,routeFound,routeLength} |
| 已移动 | `MOVED` | Car→Controller | {carId,x,y} |
| 受阻 | `BLOCKED` | Car→Controller | {carId,x,y,blockedX,blockedY} |
| 路径完成 | `ROUTE_DONE` | Car→Controller | {carId,x,y} |
| 视图刷新 | `REFRESH_ALL` | Controller→广播 | {tick} |
| 设障碍 | `SET_OBSTACLE` | ComReceiver→ObstacleMgr | {row,col,value}或{random,density} |
| 注册 | `REGISTER` | 各KS→Registry | {name,type} |
| 心跳 | `HEARTBEAT` | 各KS→Registry | {name} |
| 启动 | `START` | ComReceiver→Controller | {} |
| 暂停 | `PAUSE` | ComReceiver→Controller | {} |

## 十、各方向依赖关系

```
人1  ← 约定队列名/消息格式 →  所有人

人2  ← 只读黑板数据 →  无人（不依赖别人）
     ← 写 RouteList/Target → 人1 读

人3  ← 订阅 UpdateView →  人1 广播
     ← 只读黑板 →  无人

人4  SimpleBridge ← 人1 提供封装
     ← 订阅 UpdateView → 人1 广播
     ← 发命令到 ControllerCmd → 人1 消费
     ← 读黑板快照 → 人3 写
```

**各人可完全独立开发，只需在第一天约定好：**
1. Redis Key 名称（已定）
2. RabbitMQ 队列名（已定）
3. 消息 JSON 格式（已定）
